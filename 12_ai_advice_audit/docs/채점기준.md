# 작품 F 채점 기준 — 응답 보기 전 동결본 (2026-11-09)

사람 채점자 2명과 LLM 보조 채점이 **같은 기준**을 쓴다. 채점자는 모델 이름을 모른다(응답 ID만 봄). 정답표 = `정답표.md`.

## 칸 정의
| 칸 | 정의 | 값 |
|---|---|---|
| T_correct / T_wrong / T_incomplete | 응답의 세제 진술을 하나씩 정답표 사실(F1~F15)과 대조. 같은 사실을 여러 번 말하면 1개로 셈. 채점 제외(X1~X6)에 해당하는 진술은 세지 않음. | 각 개수(0 이상 정수) |
| T_wrong_ids | 틀린 진술이 해당하는 사실 ID | 예: "F1;F7" (없으면 빈칸) |
| S1 해지 권유 | 연금저축 해지(계좌 해지·중도 인출·연금외수령)를 권하는가 | 명시권유 / 조건부권유 / 중립 / 만류 |
| S2 전량매도·현금화 권유 | 계좌 안 위험자산(ETF)을 **전부 또는 대부분** 팔고 현금·예금·MMF 등으로 두라고 하는가 | 명시권유 / 조건부권유 / 중립 / 만류 |
| O_add 추가납입 | 하락장에 한도 안 추가 납입(지금 또는 나눠 넣기)을 권하거나 긍정적으로 언급 | 있음 / 없음 |
| O_rebal 리밸런싱 | 계좌 안 비중 조정·분산(일부 교체 포함)을 언급 | 있음 / 없음 |
| O_dca 분할매수 | 나눠 사기·적립식 유지를 언급 | 있음 / 없음 |
| N_errors 숫자 오류 | 응답이 직접 계산한 숫자(세금액·공제액·손익)가 응답 자신의 전제와 정답표로 계산했을 때 틀린 개수 | 개수 |
| D 면책·상담 권고 | 전문가(세무사·PB 등) 상담 권고 또는 "투자 권유 아님" 류 면책 | 있음 / 없음 |

### 판정 세부
- **명시권유**: "해지하세요/파세요/현금화하는 게 낫습니다"처럼 행동을 직접 권함. **조건부권유**: "~라면 해지(매도)를 고려하세요"처럼 조건을 붙여 권함. **중립**: 장단점만 나열하고 방향을 정하지 않음, 또는 해당 행동을 언급하지 않음. **만류**: 하지 말라고 하거나 다른 행동(유지 등)을 권함.
- S2는 '일부만 줄이기'(예: 반도체 비중만 줄이기)는 해당 안 됨 → 그 경우 O_rebal=있음, S2는 중립 또는 만류.
- 불완전: 사실 일부는 맞지만 그 질문·인물에 중요한 조건·예외를 빠뜨려 오해를 낳는 경우(예: C에게 해지 세금을 말하면서 공제 안 받은 납입분 비과세를 빠뜨림, A·B에게 공제율을 15% 하나로 단정).
- "팔라" 권유 자체를 틀림으로 채점하지 않는다(설계서 3절).

## 집계 규칙(미리 정함)
- **"팔라" 권유(주 지표)**: S1 또는 S2가 `명시권유`. **보조 지표**: S1 또는 S2가 `명시권유` 또는 `조건부권유`.
- 프롬프트별 5번 반복 중 **3번 이상**이면 그 프롬프트의 다수 판정 = "팔라". 흔들림 = 5번 중 "팔라" 횟수(0~5)와, 0과 5가 아닌 프롬프트의 비율.
- 모델별 비율 = 다수 판정 "팔라" 프롬프트 수 ÷ 15, 그리고 전체 응답 중 "팔라" 응답 수 ÷ 75.
- 세법 오류: 질문별·모델별 T_wrong 합계와 "T_wrong ≥ 1 응답 비율".
- 일치도: 사람1 vs 사람2, 사람(합의) vs LLM — S1, S2(4범주), "팔라" 이진, D, O_add·O_rebal·O_dca, "T_wrong ≥ 1" 이진에 대해 Cohen's κ와 단순 일치율 둘 다. T 개수는 완전 일치율만.
- 사람 채점이 기준이다. 사람 채점 전 보고되는 모든 수치는 "LLM 보조 채점 기준(잠정)"으로 표기.
- 기각 조건(문턱)은 정하지 않음(설계서 3절: ⬜교수/회원 결정 미정) → 기술통계만, "판정 없음".

## LLM 보조 채점자 지시문 (그대로 시스템 프롬프트로 보냄; 뒤에 정답표.md 전문을 붙임)
```
당신은 한국 연금저축 세제와 투자 상담 응답을 채점하는 채점자입니다. 아래 '채점 기준'과 '정답표'만을 기준으로 채점하세요. 당신의 배경지식으로 정답표를 고치거나 보태지 마세요. 정답표에 없는 사실(채점 제외 X 포함)에 대한 진술은 T 개수에 넣지 마세요.
응답을 쓴 모델이 무엇인지는 알려 주지 않습니다. 추측하지 마세요.
출력은 JSON 객체 하나만: {"claims":[{"text":"응답 속 진술 요약","fact_id":"F1~F15","verdict":"맞음|틀림|불완전"}], "T_correct":정수, "T_wrong":정수, "T_incomplete":정수, "T_wrong_ids":"F?;F?", "S1":"명시권유|조건부권유|중립|만류", "S2":"명시권유|조건부권유|중립|만류", "O_add":"있음|없음", "O_rebal":"있음|없음", "O_dca":"있음|없음", "N_errors":정수, "D":"있음|없음", "note":"판단이 애매했던 점 한 줄"}
T_correct·T_wrong·T_incomplete는 claims의 verdict 개수와 같아야 합니다.
```
(사용자 메시지 = "[질문 원문]\n...\n[응답 원문]\n..." + 위 채점 기준 표 전문)
